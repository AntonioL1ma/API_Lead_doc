LEAD API

Envie leads do seu site, landing page, CRM ou chatbot diretamente para a unidade. Cada unidade tem credenciais próprias e o lead é registrado na unidade vinculada à chave, com verificação automática de duplicidade.

Formato

Envie JSON, x-www-form-urlencoded ou form-data. A resposta é sempre JSON (UTF-8).

Segurança

Chave por unidade, limite de requisições por minuto, bloqueio automático e log de todas as chamadas.

Sem duplicidade

Contatos já existentes não geram lead novo, e reenvios com a mesma chaveEvento são ignorados.

Início rápido

  1. Receba as credenciais da integração: o código da unidade e a chave de API (48 caracteres, ex.: 3f9a1c0b...).
  2. Envie um POST para index.php?AC=ActionLeads&a2=incluir com os cabeçalhos X-Unidade e X-Api-Key.
  3. Leia o campo codigo da resposta: LEAD_CRIADO significa sucesso.

Autenticação

            
Toda requisição precisa do código da unidade e da chave de API dessa unidade.


            

                
CabeçalhoAlternativa no corpoDescrição

                
                    
X-UnidadeunidadeCódigo da unidade (ex.: 00).

                    
X-Api-KeychaveChave de 48 caracteres hexadecimais (0-9, a-f).

                
            


            

                Use a chave somente no servidor.
                Em JavaScript de página (navegador) ela fica visível para qualquer visitante.
                Formulários de site devem enviar para o seu back-end, que chama a API.
            

            

                Trate a chave como uma senha: guarde em variável de ambiente ou cofre de segredos, nunca no
                repositório de código. Se ela vazar, solicite uma nova; a anterior deixa de funcionar na hora.
                Sempre use HTTPS em produção.

Reenvio seguro (chaveEvento)

            

                Envie uma chaveEvento única por envio de formulário (ex.: o ID da submissão).
                Se a mesma requisição for repetida, por timeout ou erro de rede, a API reconhece
                a chaveEvento e não cria outro lead.
            

            

                
1º enviochaveEvento: form-881201 LEAD_CRIADO

                
→

                
ReenviochaveEvento: form-881200 CRIADO: false

            

        


        
        

            
Limites e bloqueio

            

                

                    
30 / minuto

                    
Limite padrão por chave (pode variar por unidade). Cabeçalhos X-RateLimit-Limit e X-RateLimit-Remaining mostram o consumo.

                

                

                    
Bloqueio de 30 min

                    
A requisição que passa do limite bloqueia a chave. O cabeçalho Retry-After informa os segundos restantes.

                

                

                    
3 bloqueios em 24h

                    
A partir do 3º bloqueio em 24 horas, a chave fica bloqueada sem prazo até ser liberada manualmente.

                

                

                    
10 erros / minuto por IP

                    
IP com muitas tentativas de chave inválida é recusado por 1 minuto.

Boas práticas

            

                
SituaçãoRecomendação

                
                    
Timeout ou erro de redeReenvie com a mesma chaveEvento; o lead não será duplicado.

                    
HTTP 500Tente de novo após alguns segundos, com espera crescente (ex.: 5s, 30s, 2min), no máximo 3 vezes.

                    
HTTP 429Pare os envios e respeite o cabeçalho Retry-After. Não insista: novas tentativas não liberam a chave.

                    
HTTP 401, 403 ou 422Não reenvie: corrija as credenciais ou os dados antes.

                    
HTTP 200 com CRIADO: falseSucesso da integração; o contato já existia. Não é erro.

                    
Envios em loteDistribua ao longo do tempo para ficar abaixo do limite por minuto.

                    
RegistrosGuarde chaveEvento, codigo e ID_LEADS de cada envio para conferência.

Dúvidas comuns

            

                Recebo CHAVE_INVALIDA ou UNIDADE_INVALIDA
                
Confira se a chave tem exatamente 48 caracteres, sem espaços, e se o código da unidade é o mesmo
                informado junto com ela. Cada chave só funciona com a sua unidade.

            

            

                A resposta veio 200, mas o lead não apareceu
                
Veja o codigo: LEAD_EXISTENTE, CADASTRO_EXISTENTE, CADASTRO_AMBIGUO e CONFLITO_ENTRE_LEADS não criam lead novo (dados.CRIADO = false).

            

            

                Como cadastrar o lead numa campanha?
                
Envie campanha com o ID ou o nome exato de uma campanha ativa da unidade. Se não existir, a API responde 422.

            

            

                Telefone internacional
                
Envie pais com o DDI (ex.: 351) ou o telefone já com + (ex.: +351 912 345 678).

            

            

                Minha chave foi bloqueada. O que fazer?
                
Bloqueios por excesso de requisições são liberados sozinhos após o prazo indicado em
                Retry-After e em dados.BLOQUEADO_ATE. Quando BLOQUEADO_ATE vier
                null, o bloqueio é sem prazo: solicite a liberação ao responsável pela integração e
                revise o volume de envios.

            

            

                Posso chamar a API direto do formulário do site (JavaScript)?
                
Não. A chave ficaria visível para qualquer visitante. Envie o formulário para o seu servidor
                e faça a chamada à API a partir dele.

            

            

                Existe ambiente de testes?
                
As chamadas são processadas em produção. Para validar a integração, use dados claramente
                identificáveis como teste (ex.: nome "Teste Integração") e avise a unidade.
